[]2. Local stateful host and one playbook

Implement the session boundary without a cloud control plane. Initial local host targets macOS/Linux; Windows transport and remote operation are not claimed. Until slice 3, scan checkpoints return explicit unavailable/blocked diagnostics, never fake successful scan results.

2.1 Deliverables

  • []Use node:net local IPC in a private per-user directory with restrictive permissions and bounded message sizes. SDK/CLI use the same seven commands. No unauthenticated TCP/HTTP listener or new RPC framework. Define framing, request correlation and replay limits before implementing the transport.
  • []Implement owned sessions and authorized borrowed targets through a Playwright adapter. The host resolves target IDs; clients cannot supply arbitrary browser endpoints or self-grant policy permissions. Ending a borrowed session detaches rather than terminating its browser.
  • []Keep session state alive across client disconnects. Bound operation/event retention, make gaps explicit and coordinate conflicting page actions. Cancel cooperatively or with permitted host enforcement; never replay uncertain side effects after reconnect or loss.
  • []Add one trusted dialog-open-close playbook against a controlled local fixture. Declare origin/action permissions, inputs, prerequisites and scan checkpoints. Record actual checkpoint state and failures; no arbitrary agent-authored execution, real login credentials or business submissions.
  • []Keep secrets, audit/redaction and access decisions at the host boundary. This first single-user local host is not production multi-tenant isolation, durable crash recovery or an enterprise identity suite.
