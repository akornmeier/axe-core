Purpose

Build beyond a modernized axe-core: a programmable accessibility and design-system policy engine. Organizations should turn their component contracts, accessibility requirements and design decisions into versioned, testable rules. AI agents should help author and maintain those rules; deterministic execution and review should make them trustworthy.

Scope: modern tooling, engine architecture, rule-logic innovation, configurable policy packs, a typed rule-authoring SDK, an agent-facing contract and measured runtime acceleration. Keep canonical axe-core separate for comparison; do not maintain its legacy tooling inside Propellr. The new API boundary still requires an explicit decision. Rule behavior can improve through explicitly reviewed changes; compatibility is a migration constraint, not a ban on invention.

Delivery: six slices cover foundation, tooling, core boundaries, a working policy/SDK pilot, acceleration and agent authoring, then retirement of old paths. Prototype the platform contract as soon as focused correctness gates exist; do not make a formatter migration or total legacy cleanup a prerequisite to learning. No automated publishing, live channels, customer-data ingestion or downstream-repo edits without separate authorization.

Solution: a small engine with a powerful rule surface

Separate analysis, policy and execution so new rule logic no longer depends on ambient engine state or build-time string wiring. Keep existing checks usable through adapters; prove new contracts on real enterprise cases before migrating the full corpus. Lean code means fewer hidden dependencies, not fewer capabilities.

PNPM, Vite, Vitest, Playwright, TypeScript and Oxc support this work. They are infrastructure choices, not the product strategy.

Until then, preserve existing contracts; facade references below are provisional, not a settled requirement.

Carry forward PR #5's explicit host boundaries, independent state, structured evidence and reviewed verdict-parity concepts. Keep snapshot-first CDP, packed FlatTree, mandatory workers, many packages/reporters and history/MCP infrastructure as evidence-gated experiments. Snapshot fidelity and cross-subtree after-functions must be proved before choosing transport or scheduling. A DOM ancestor failure alone is not evidence of a shared root cause.

Existing axe already supports custom checks, rules and options through axe.configure(). The opportunity is to make that capability discoverable, composable, isolated, explainable and safe to extend. Two authoring paths: a small declarative composition format for existing facts and predicates, plus a typed evaluator escape hatch for novel logic. Both produce one normalized rule contract. Enterprise configuration is a product surface

  • Rule packs: package a versioned set of rules, option schemas, fixtures, documentation references and compatible engine/capability ranges. Namespaces prevent an enterprise rule from silently replacing a built-in rule. Resolve and pin dependencies before a scan; never fetch or execute a remote pack during evaluation.
  • Policy layers: define precedence as pack defaults → organization → project → component/state. Organization-locked requirements cannot be weakened by lower layers. Duplicate same-level selectors with conflicting settings fail resolution instead of depending on array order.
  • Explainability: show the effective value, its source, matched scope, pack/rule version and policy digest. Exceptions need a bounded target, owner, rationale and expiry; retain the original finding and exception status rather than hiding it.
  • Separate claims: accessibility findings and design-system policy findings are distinct categories. Enterprise severity is not WCAG impact. A brand-token mismatch must not become a claimed WCAG failure, and an enterprise override must not relabel a known accessibility violation as a pass.
  • Component contracts: begin with explicit component identity, state and version supplied by a reviewed manifest or test instrumentation. Framework adapters can follow. DOM inspection alone cannot reliably infer source components, prove token provenance or inspect every closed shadow root.

Runtime speed is an architectural workstream

  • Measure first: instrument candidate selection, fact computation, evaluator work, frame transport and result construction. Reuse existing performance hooks; distinguish full-scan CPU, wall time, memory and local edit-to-result latency.
  • Share expensive facts: memoize within a scan using node identity, root/frame, options, policy digest and relevant environment inputs. Batch read-only style/geometry work where safe. Do not cache arbitrary legacy evaluator results unless purity and dependencies are known.
  • Compile selected work: build a validated capability/dependency plan for the selected pack set. An enterprise-only scan should not load or initialize every built-in rule. Preserve outcome evidence; short-circuit only when rule semantics permit it.
  • Incremental execution: track affected nodes and rule dependencies between explicit scan epochs. Cover ancestor/sibling relations, stylesheet/theme changes, fonts, resize, focus, frames and document-wide constraints. MutationObserver alone is insufficient. Unknown dependencies, opaque legacy rules or unstable pages fall back to a full scan; cancellation/timeout/staleness is never a pass.
  • Concurrency: DOM/layout reads remain on the owning page thread. Consider workers only for measured pure computations over serializable facts. No blanket Promise parallelism over mutable DOM or shared engine state.
  • Stretch hypotheses: target 2× faster full scans on representative enterprise pages and 10× faster rechecks after a small component edit, compared with a pinned full-scan baseline on the same environment. Include extraction, invalidation, serialization and memory cost. These are experiments, not promises or substitutes for accuracy.

AI authors rules; the engine establishes evidence

  • Structured contract: publish schemas for manifests, configuration, fixtures and diagnostics. Outcomes distinguish pass, fail, inapplicable and inconclusive; operational errors remain explicit. Evidence includes rule/policy versions, expected/observed values, target, scope and reproduction context. A numeric model confidence is not a correctness guarantee.
  • Independent verification: agents may scaffold code, fixtures and proposed fixes, but their own tests cannot certify their rule. Require maintainer-owned holdouts, counterexamples and an accessibility/design-system owner review before promotion. Scan execution requires no model calls.
  • Trust boundary: generated code, package dependencies and text from pages/docs are untrusted. Run candidate evaluators in disposable test processes/browser contexts with blocked egress, no credentials and sanitized fixtures. Enforce wall-clock termination at the host; a synchronous infinite loop cannot be stopped by an in-page timeout. TypeScript, schema validation and a same-page JavaScript wrapper are not sandboxes.
  • Runtime tiers: declarative packs execute only approved primitives; arbitrary evaluator code must be reviewed and trusted before in-page execution. Capabilities document requirements but do not restrict arbitrary JavaScript by themselves. Never auto-enable a newly generated pack in enterprise enforcement.
  • Governance: record author/model provenance, requirement references, reviewed tests, compatible versions and content digest. Roll out draft → advisory → enforcing, compare rule/policy version diffs and support a pinned rollback. Redact DOM snippets and client identifiers in diagnostics by default; do not send enterprise fixtures to model providers without authorization.
  • Fixes: remediation suggestions are separate artifacts, validated against fixtures and existing accessibility checks. No automatic page mutation or production fix application during a scan.

Testing and contributor workflow

  • Fast loop: pure source tests in Node; DOM source tests in Chromium with the same metadata plugin as the build. Watch mode must notice rule/check JSON, templates and locale edits, not only TS files. No rebuilding all four bundles on every edit.
  • Artifact lane: run rule integration, ACT/APG and API compatibility against fresh dist output. Keep source tests and artifact tests distinct so fast imports cannot hide packaging bugs.
  • Browser policy: Chromium-focused local watch; Chromium, Firefox and WebKit correctness on PRs. Start with deterministic bounded workers; shard only after measuring file durations. Do not share mutable axe/page state concurrently.
  • Conformance: serve whole documents, assets and iframe origins through one test-owned server. Fresh page/context state per case; inject the freshly built engine, including child frames as required. Keep existing expected outcomes and documented exclusions.
  • Useful evidence: focused failures, trace/screenshot attachments only on browser failures, zero automatic retries initially. Any quarantine needs owner, reason and expiry.
  • Coverage: establish source-mapped Node and Chromium coverage first. V8/CDP coverage is not a Firefox/WebKit coverage strategy. Gate correctness in all three; use coverage to identify missing behaviors, not force hundreds of low-value tests to reach an invented 85%.
